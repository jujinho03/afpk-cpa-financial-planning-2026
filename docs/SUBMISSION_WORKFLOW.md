# 제출 자료와 Git 관리 방법

이 안내는 팀의 공개 코드와 비공개 제출 자료를 관리하는 방법을 설명합니다. 최신 참가작의 파일명·검수 결과·미확인 사항은 팀장이 관리하는 비공개 준비팩에서 확인합니다. 이 공개 문서에 원고나 서명 파일을 첨부하지 않습니다.

## 어떤 자료를 어디에 보관하나

| 자료 | 보관과 사용 |
|---|---|
| 계산 코드·합성 입력·재현 결과·공개 작업 안내 | Git으로 버전을 관리하고 PR에서 검증 |
| 참가작 본문·AI 활용 기술서·통합 DOCX/HWP | 비공개 작업 폴더에서 편집·검수 |
| 개인정보 동의·제출확인서·서명 스캔 | 비공개로 보관하고 접수에 필요한 파일만 제출 |
| 접수 준비팩 ZIP | 내부 준비용. 실제 업로드 파일을 고르기 위한 묶음 |
| 최종 점검 보고 | 무엇을 검사했고 무엇이 남았는지 확인하는 기록 |

[공식 공고](https://www.ifpk.org/?data_usn=181814&mnu_usn=67&mode=view&page_no=1)는 본문과 부록을 합친 DOCX/HWP 한 파일과 전원 서명이 있는 별도 서류를 요구합니다. 직접 만든 도구의 선택 제출물은 별도 결정 대상입니다. 준비팩 ZIP을 선택 도구 ZIP으로 간주하지 않습니다.

## 준비팩을 사용하는 순서

1. ZIP을 압축 해제하고 읽기 안내와 최종 점검 보고를 엽니다.
2. 보고서 전체를 읽고, 점검 보고에 남은 실제 확인 항목을 처리합니다.
3. 공식 확인서를 출력해 실제 동의·날짜·전원 자필 서명을 작성하고 스캔합니다.
4. 팀명과 서명 스캔을 확정한 뒤 제출 규칙에 맞게 파일 이름을 적용합니다. 파일명 도구가 있다면 지원하는 입력과 원고 해시를 먼저 확인합니다.
5. DOCX/HWP와 서명 스캔을 각각 열어 최종 확인하고, 실제 접수 계정으로 업로드합니다.
6. 접수 완료 화면이나 메일, 제출 시각·파일명·해시를 비공개로 보관합니다.

내용을 수정했다면 예전 해시·쪽수·검사 결과를 그대로 사용하지 않습니다. 파일 이름만 바꾼 경우와 문서 내용을 바꾼 경우를 구분합니다. 자동 검사는 실제 동의·사람의 통독·서명·접수를 대신하지 않습니다.

## Git 용어와 실제 작업

| 작업 | 쉬운 뜻 | 확인할 것 |
|---|---|---|
| fetch | 원격의 새 커밋 정보를 가져옴 | 작업 파일을 자동으로 합치지 않음 |
| pull | 원격 변경을 로컬 브랜치에 반영 | 먼저 작업 트리 확인, 기본은 fast-forward만 허용 |
| commit | 선택한 변경을 로컬 이력으로 저장 | stage된 파일 목록·민감정보 확인 |
| push | 로컬 커밋을 원격 브랜치에 올림 | 공개 범위와 올릴 브랜치 확인 |
| PR | 브랜치 변경을 검토·병합할 제안 | 변경 내용·검증 결과·가정과 AI 영향 기록 |
| merge | 검증한 브랜치를 main에 통합 | 실제 head와 CI 확인, 사람 리뷰 여부를 사실대로 기록 |

공개 문서를 수정하는 예시는 다음과 같습니다. 브랜치 이름과 파일은 실제 작업에 맞춥니다. 기존 변경이 있다면 먼저 보존하고, 일괄 stage 대신 의도한 파일만 지정합니다.

```sh
git status --short --branch
git fetch origin
git switch main
git pull --ff-only origin main
git switch -c docs/my-update
# 공개할 문서 편집 후
git add -- docs/SUBMISSION_WORKFLOW.md
git diff --cached --stat
python scripts/check_repository.py --staged
git commit -m "docs: explain submission workflow"
git push -u origin docs/my-update
```

그다음 PR에서 변경과 검사를 확인해 병합하고, 로컬로 돌아와 `git switch main`, `git pull --ff-only origin main`을 실행합니다. 로컬 HEAD와 origin/main이 같고 작업 트리가 깨끗한지 확인합니다. 실제 필요한 검사 명령은 [기여 안내](../CONTRIBUTING.md)를 따릅니다.

Git 동기화는 Git이 추적하는 파일에 적용됩니다. ignore된 비공개 원고·서명·준비팩은 push/pull로 백업되거나 전달되지 않습니다. 해당 파일은 접근이 제한된 별도 백업으로 관리합니다. 이미 공개된 파일은 나중에 ignore 규칙을 추가해도 과거 이력에서 사라지지 않습니다.

최종 상태는 코드 반영·문서 검수·사람 승인·서명·접수를 나눠 기록합니다. CI 성공을 전체 제출 완료로 표시하지 않습니다. 기존 브랜치 삭제·force push·공개 범위 변경은 별도 승인 없이 하지 않습니다.
