# 데모와 프로젝트 바이블의 차이 분석

기준일: 2026-11-12 KST
상태: `NOT_ASSESSED` — 데모 원본 소스·실행 결과 대기

기준 문서: [프로젝트 바이블](../bible/AFPK_CPA_아이디어_기획서.md), v1.0, 2026-11-12. 원본 데모를 확인하지 못했으므로 아래 표는 비교할 기준과 검증 절차를 고정한 것이다. 실제 차이·완료율·성능 점수를 산정하지 않는다.

## 상태 정의

- `NOT_ASSESSED`: 소스나 실행 증거가 없어 판단하지 못함
- `VERIFIED`: 코드와 실행 결과로 확인함; 파일·명령·출력 근거 필요
- `PARTIAL`: 구현 일부를 확인했으나 기준 일부 미충족
- `NOT_IMPLEMENTED`: 실제 코드와 실행 검토 결과 해당 기능이 없음을 확인함
- `DIFF_FOUND`: 입력·시점·계산·표시 차이를 확인함; 원인·영향 기록 필요
- `OUT_OF_SCOPE`: 이번 단계의 구현 범위에서 제외함; 없는 기능이라는 판정은 아님

## 비교에 사용할 재현 기준

v4 기본 모형은 현재 다음 값을 계산한다. 데모가 이를 계산한다는 뜻은 아니다. 단일 값만 맞추지 말고 입력·월별 행·집계식부터 확인한다.

| 기준 경로 | 2028.05 원시잔액 | 최초 안전자금 하한 위반 |
|---|---:|---|
| A/U | -555.0 | 2027.10 |
| B/U | 1,025.0 | 없음 |
| C | 2,833.8 | 없음 |
| D/U | 845.0 | 없음 |
| D/U, 정규직 급여 2개월 지연 | 545.0 | 2028.03 |

60개월 가중 지표: A 5,259.216, B 6,062.210, C 6,716.700, D 5,853.492. p/q/감소폭은 검증된 개인 확률이 아니다. 화면의 반올림과 계산 내부 정밀도를 분리해 비교한다.

## 원인 분석 절차

1. 표시값의 파일·함수·API·고정 데이터 위치를 식별한다.
2. 데모와 Python의 동일 입력 스냅샷, 금액 단위, 기준일, 기간, 경로를 기록한다.
3. 월별 소득·지원·지출·상환·잔액에서 최초 차이 행을 찾는다.
4. 계산 차이와 화면 반올림·캐시·표시 차이를 나눈다.
5. 차이의 원인·고객 영향·권고 영향·검토자를 기록한 뒤 변경한다.
6. 변경 후 기존 기능 회귀와 Python 대조를 재실행한다.

표에 숫자를 하드코딩하여 맞추거나, 기존 데모가 어떤 모형을 사용하는지 모르는 상태에서 계산기를 중복 개발하지 않는다.

## 데모와 독립적으로 알려진 v4 확인 과제

이 항목은 데모 결함 판정이 아니다. 기존 자료 감사에서 나온 후속 검토 과제다.

- 안전자금 하한 위반과 현금 음수·미충당액 발생 시점을 구분해야 한다.
- B/U의 1,025는 2028.04 일반직 전환을 포함하며 시간제 지속만의 값이 아니다.
- D의 시간제 급여 지연은 `job_delay`로 직접 바뀌지 않는다.
- 연도를 넘는 장기 지연에서 월 튜플 생성 방식의 결함이 알려져 있다.
- v4 PDF 생성기의 별도 18개월 계산과 현재 바이블의 경로 정의가 다르다.
- 실제 ICL 의무상환·세부 잔액 추적은 미완료다.

위 제한을 초기 구축에서 수치 변경으로 해소했다고 주장하지 않는다. 재무적 변경은 별도 검토·테스트·변경기록이 필요하다.
