# 데모와 프로젝트 바이블의 차이 분석

기준일: 2026-11-12 KST. 인수 원본: 설경민의 `import/afpk-demo` 커밋 `bd5a62518f07f4f738a1c1ec69d4c697d7345ccb`.

**결론: Rust 데모는 Python v4의 동일 수식 포트가 아니라 별도 가정의 확장 모형입니다.** 같은 프로젝트 주제를 구현하지만 초기 급여·근로 시작월·안전자금·D 전환·할인 지표 정의가 다릅니다. 두 모형의 결과를 같은 입력의 독립 검산이라고 설명하거나 화면 수치를 하드코딩해 맞추지 않습니다.

비교 기준은 [2026-11-12 프로젝트 바이블](../bible/AFPK_CPA_아이디어_기획서.md)과 [Python v4](../../src/afpk_cpa/financial/model_v4.py)입니다. Rust의 원본 설명은 2026-11-11의 다른 18쪽 기획서를 참조합니다. 현재 제공된 바이블는 표지 포함 17쪽이며, 그 원본을 수정하지 않습니다.

## 상태와 근거

- `SOURCE_CHECKED`: 실제 파일·함수·기본값을 읽어 구현을 확인했습니다. 실행 성공을 의미하지 않습니다.
- `DIFF_FOUND`: 수식·가정·결과 정의의 차이를 확인했습니다. 차이 자체를 버그라고 단정하지 않습니다.
- `RUNTIME_CHECK`: 설치·실행·테스트 결과는 [인수 보고](DEMO_INTAKE_REPORT.md)에 기록합니다. 이 문서의 소스 검토와 구분합니다.

금액은 비교 편의를 위해 **만원**으로 환산합니다. Python은 만원 단위 float, Rust는 원 단위 정수와 Decimal을 사용합니다. 모두 합성 고객 가정입니다.

## 비슷한 숫자가 같은 경로라는 뜻은 아니다

| 경로 | 현재 Python v4의 2028.05 잔액 | Rust 원본 회귀 테스트가 고정한 이전 기획서 기준선 |
|---|---:|---|
| A/U 또는 A 기준선 | −555.0 | `Unresolved`, 임금 미입력: −595.0 |
| B/U 또는 B 기준선 | 1,025.0 (2028.04 일반직 포함) | `Unresolved`, 임금 미입력: 845.0 (시간제 지속) |
| C | 2,833.8 | 임금 미입력 기준선은 `missing`; 현재 기본값은 270과 2027.02 사용 |
| D/U 또는 D 기준선 | 정상 845.0 / 급여 2개월 지연 545.0 | 임금 미입력 기준선은 2028.04 하한 위반, 잔액 330.0 |

Rust의 `PDF_BASELINE`은 `jobWage`, `traineeSalary`, `cpaSalary`만 null로 만든 프로필입니다. 현재 바이블·Python v4의 전체 가정을 복원하는 프리셋이 아닙니다. 테스트의 기대값은 [원본 Rust 회귀 테스트](../../apps/demo/backend/src/finance/cpa_gap/tests.rs)에 들어 있습니다. 위 오른쪽 수치는 실행 성공을 대신하는 것이 아니라 해당 테스트 명세의 값입니다.

## AI 기록 인수와 검증 범위

[인수된 기록](../../apps/demo/ai/evaluations/cpa_experiment_runs.json)에는 E1~E8 **8개 run·23개 주장**이 있습니다. 각 run에 도구·provider·model·실행 시각·시스템 프롬프트·입력·출력이 있으며, 제공자는 2026-11-11 서버를 통해 Gemini를 실행한 원출력이라고 기록했습니다.

- 이번 인수에서는 파일과 메타데이터·내용을 확인했습니다. API를 다시 호출하거나 제공자측 요청 이력으로 진위를 독립 확인한 것은 아닙니다.
- `aiReview`는 Claude Code의 **AI 1차 의견**입니다. 인간 최종 판정·검토자·수정 권고 승인이 기록돼 있다는 뜻이 아닙니다.
- 원출력 프롬프트는 안전자금 360 고정·시험 후 수험비 5 지속 등 **이전 데모 가정**을 사용합니다. 현재 Python v4에 대한 실험 결과로 이름만 바꿔 사용하지 않습니다.
- 실험 번호도 완전히 같지 않습니다. 루트 바이블의 E5는 근로 시작·첫 급여 구분, 데모 E5는 자격 미확인 지원금입니다. 루트 E6는 공부시간 손실·C 취업 지연, 데모 E6는 장기 가치 비교와 중간 자금 부족입니다. [AI 증거 인덱스](../../ai_evidence/README.md)에서 질문 의미로 매핑하며 ID 일치만으로 기존 실험을 완료 처리하지 않습니다.
- 검증 화면은 `defaults + PDF_BASELINE + claim.patch`로 Rust API를 호출합니다. 원래 입력과 현재 UI 사용자 입력·Python 기준값은 별개입니다.
- 계산상 일치/오류 판정과 공식 제도 확인·인간 판단은 구분해야 합니다. 인간 검토와 고객 권고의 수정 전후가 채워져야 공식 AI 기술서의 완전한 증거 묶음이 됩니다.

## 병합 시 처리 원칙

1. Python v4의 원본·가정·표·그림은 보존합니다. 기본 결과를 Rust 결과로 교체하지 않습니다.
2. 데모를 **별도 가정의 Rust 확장 모형**으로 표시하고, 루트 참조 모형과 차이를 사용자가 찾을 수 있게 연결합니다.
3. 원저작자 README·이전 기획서 수치는 인수 기록으로 보존하되 현재 프로젝트의 같은 가정 검산 결과로 홍보하지 않습니다.
4. 기존 데모 기능을 전면 재작성하지 않습니다. 단일 수치로 통합하려면 입력 스키마·월별 경로·할인 지표 정의를 먼저 합의하고 회귀·교차 검산을 별도 수행합니다.
5. 실행·빌드·API 검증 결과는 인수 보고에 실제 명령·환경·결과로 기록합니다. 샘플 JSON·스크린샷·과거 README의 성공 주장을 현재 실행 실적으로 대신하지 않습니다.
