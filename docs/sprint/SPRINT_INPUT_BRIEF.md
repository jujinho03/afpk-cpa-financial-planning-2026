# 3인·3일 실행계획의 입력 브리프

기준일: 2026-11-12 KST
상태: 사전 입력자료; 최종 일정·개인별 프롬프트·PDF는 미제작

프로젝트는 「합격해도 끝나지 않는다」, B안 가상 고객 재무설계다. 바이블의 마감은 2026-11-16 23:59 KST이며, 예정 집중 작업일은 11월 13~15일이다. 최종 일정은 데모 인수 결과와 각 팀원 가능시간을 확인한 뒤 잠근다.

## 완료 기능을 정하는 기준

[데모 기능 목록](DEMO_FEATURE_INVENTORY.md)과 [차이 분석](../demo/DEMO_BIBLE_GAP_ANALYSIS.md)에 코드·실행 증거가 있어야 데모 기능을 완료로 분류한다. 현재는 데모 전체 `NOT_ASSESSED`다. 소스가 없다는 이유로 모든 기능을 새로 개발하는 일정으로 바꾸지 않는다.

Python 재현·협업 문서·CI 등 이번 구축 산출물의 실제 통과 여부는 루트 README, 테스트 결과 및 GitHub 상태에서 확인한다. 이 브리프 자체는 실행 통과나 원격 push의 증거가 아니다.

## 선행 의존성과 품질 게이트

1. 설경민의 `feature/demo-import` 원본 업로드 → 출처·비밀정보·이력 확인 → 박동찬의 원본 실행 확인 → 기능 분류 → 인수 PR·통합 범위 확정. `main` 직접 업로드와 소스 미수령 상태의 통합 PR은 하지 않는다.
2. 가정 원장·기준 모형 고정 → 동일 입력 대조 → 계산 차이 원인 판단 → 주진호 검토 → 연결 변경.
3. E 실험 판정 기준 → 실제 실행·원출력 보존 → 독립 검증 → 수정/오류 없음 기록 → AI 기술서.
4. 본문+부록 → 숫자·출처·익명성·형식 검토 → 팀원 서명 → 제출 담당 확인.

데모 입력이 없어도 가정·기존 모형 검산·AI 실험 설계·본문 구조·저장소 협업은 진행할 수 있다. 데모 구현 내용에 의존하는 개발량과 최종 일별 배분은 유보한다.

## 범위 통제

P0는 필수 재무설계 본문·AI 기술서 및 제출서류 준비, P1은 정확성·증거·기존 데모 통합, P2는 선택 UI·추가기능이다. 기존 기능을 다시 구현하거나 원본을 받기 전에 새로운 프레임워크를 결정하지 않는다. 배포, 유료 서비스, 공개 전환, 최종 3일 PDF와 공식 참가작 작성은 이번 초기 구축 범위에서 제외한다.

## 다음 단계에서 확정할 입력

- 설경민의 데모 업로드 커밋·실행 성공 여부·기능별 증거와 유지해야 할 동작
- 계산 중복 여부·최초 차이 행·금융/AI/환경별 검토자
- 각 팀원의 가용시간과 실제 초대 수락 상태
- 인수 완료일과 제출용 양식 확보 여부
- 실패 시 포기할 P2 목록과 데모를 제외해도 완성할 P0 경로

이 입력을 채운 뒤 주진호의 다음 단계 지시에 따라 최종 3인·3일 계획과 개인별 지시 프롬프트를 작성한다.
