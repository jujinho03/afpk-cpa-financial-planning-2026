## 범위 잠금 규칙

1. 완료된 데모 기능은 재개발하지 않는다. 실제 기능 목록을 채운 후 작업 원장을 수정한다.
2. 금융 계산·고객 권고 변경은 근거·영향·테스트와 주진호 검토가 필요하다. 이번 인수에서는 기존 결과를 보존한다.
3. AI 원출력 또는 오류를 만들어 실적으로 기록하지 않는다. 오류가 없으면 오류 없음으로 남긴다.
4. Git 이력 재작성·강제 push·기능 삭제·배포·유료 결제·공개 전환은 이 원장의 승인으로 수행하지 않는다.
5. 실행계획을 잠글 때 담당자·입력·출력·검수자·완료 기준을 연결하고, 데모 미확인 작업에 임의 기간을 배정하지 않는다.

## 계획 확정 전 우선 확인

설경민의 `feature/demo-import` 원본 업로드와 실행 정보가 가장 큰 통합 의존성이다. 업로드 후 인수 PR에서 박동찬이 실행·빌드·테스트를 확인한다. `main`에 직접 업로드하지 않는다. 이를 기다리는 동안 P0-01~04와 P1-01·06을 진행한다. 데모가 늦게 도착하면 P2를 제거하고 인수·재현 가능한 최소 연동만 검토한다. 데모 미수령을 새 데모 개발의 근거로 사용하지 않는다.
